# Three-head terminal Monte Carlo prerequisite

This opt-in source prerequisite samples and updates expansion, card and purchase actors from one
unchanged behavior trajectory. It introduces no critic, phase alias, reward shaping, league or live
policy activation. Existing two-head trajectories, GAE objectives, continuation checkpoints and
expansion-only contracts retain their current validation and defaults.

## Behavior and evidence

A new versioned three-head input and episode bind the controlled expansion actor, card actor and
purchase actor independently, including their models, dictionaries, priors and sampled likelihoods.
Rivals remain the explicit fixed G3 bundle; ordinary M8, expansion reference, token ordering and F0
bindings remain explicit. The expansion reference recommends once before the learned full-offer
sample; no later overlay may overwrite that sample. Other phases use the actual card/purchase
controllers. All records retain the original actor-visible observation, action index, probability,
log probability, value, actor seed and absolute player-decision number. Forced rows are included.
The three phase streams share one original terminal result and never overlap absolute numbers.

The native owner validates the complete controller and canonical replay. A separate Python reader
verifies the new manifest, source/snapshots, each head's existing observation and likelihood contract,
the sampled command and terminal subject. It does not coerce this episode into a legacy two-head
episode or expansion-only collection. Row preparation preserves every original actor input and
behavior field; detached terminal labels are separate.

## Objective and continuation

Each recorded decision receives the existing normalized terminal reward minus the fixed baseline
0.5. There is no bootstrapping or phase clock: gamma/lambda and predictor descriptors are not
applicable. Each head uses its own mean over recorded decisions, the existing PPO clipping and
whole-epoch KL rollback arithmetic, and the fixed existing actor-only optimizer configuration.
Only the existing five actor tensors train. All value parameters and value momentum are excluded.
No new independent trust-region guarantee is claimed for the combined policy.

A new typed MC phase view and continuation bind EXPANSION, CARD or PURCHASE explicitly, together
with all three behavior model identities, the exact source/rows/terminal-label subject, the baseline,
objective version and optimizer configuration. The intrinsic five-slot Adam validation is reused;
legacy predictor-based or expansion-only carries are never accepted through a missing-identity
shortcut. Initial weights may be supplied by the eventual experiment, but all three optimizers
start fresh for this MC recipe. Scientific weights and initialization are not opened during this
source prerequisite.

Before any update, the atomic owner validates every head and every supplied carry. It then updates
each head against the same frozen collected behavior, retaining independent phase diagnostics.
It publishes the next three-head bundle only after all three phase outputs, checkpoints, source
bindings and finished receipts verify. A failed or interrupted phase leaves diagnostics and no next
bundle. Later batches may consume only a fully published predecessor; optimizer slots never cross
heads. A phase with no recorded rows must be represented explicitly and cannot silently reset carry.

## Implementation ownership

The native work adds a small typed input/controller/episode/collector/store owner and focused tests,
reusing existing simulation, callback, likelihood and replay owners. The Python work adds a strict
three-head reader, typed MC objective/carry and atomic publisher, reusing the established numerical
loss, minibatch, optimizer and rollback owners through an explicit new objective branch. Existing
readers and objective types remain strict. Changes to install packaging are limited to this closure.

Verification covers source/model/dictionary/phase tampering, full-offer expansion sampling and
reference precedence, absolute-number and seed fidelity, unchanged C/P evidence, fresh and continued
Adam for all three phases, frozen value tensors, accepted and rejected epoch rollback, and failed
third-phase publication. Synthetic actual optimizer steps are UNIT evidence only. Existing affected
legacy guards and default arithmetic are checked alongside the new focused tests. Native formatting
precedes format checking, and builds are serialized in this checkout.

## Prospective experiment, not authorized execution

The proposed first substantive study is 32 matched batches of 256 worlds per arm: joint E+C+P
versus E-only, identical initial E and G3 C/P, fresh MC Adam, fixed raw G3 rivals and common audited
world banks. All learning and selection choices must be fixed before a later launch review. There
is no interim arena or checkpoint search. A joint-only operational proof establishes fidelity and
storage, not cross-phase coordination. No seeds, models, retained rows, games or scientific fits are
authorized by this document.

The observed expansion-only archive cost of approximately 61 MiB per batch makes 32 matched
batches about 3.81 GiB before extra C/P records and numerical evidence. Provisionally allow
12–16 GiB retained data; freeze exact limits and the operational prefix after measuring owned byte
accounting. A 64-batch comparison would double learning cost and needs a separate decision.
Collection/update timing must use actual existing owner costs before fixing the eventual wall clock.
