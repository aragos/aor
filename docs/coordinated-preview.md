# Coordinated local preview contract

This source prerequisite prepares one optional local profile, `aor-coordinated-83-support-1`.
It does not install an asset or authorize a preview. The candidate is the exact final mean16
four-head bundle from family83, with the existing `known-own-chaos-support-1` conditioning on
Card/Purchase only. Its fresh qualification compares this complete behavior with G3 plus the same
conditioning. The raw family83 development result does not qualify the conditioned profile.

## Execution

The server already depends on common AI. A cached, explicitly configured JVM policy loads the
immutable model subjects once. Qualification and the server call the same common four-head selector;
the server never depends on the training module. Card uses ordinary M8, Purchase uses frozen F0,
and both retain their existing actor-seed/uniform owners before Support1 conditions probabilities.
Expansion/Token use the unchanged full G3 reference command, current-minus-original raw neural
residuals, the frozen calibrated scales, margin1 and reference-first ties. The old sampled territory
decoder is not used.

Only newly created HARD seats in the exact current-rules four-player qualified configuration receive
the new stored profile identity and immutable asset SHA. Existing seats, other setups and difficulties
retain their browser policy path. Startup configuration is opt-in and local-only; a configured invalid asset fails startup.
A saved seat requiring the new profile cannot silently fall back when its asset is unavailable.

Creator-authorized bot work may contain a typed proposal with profile, asset identity and canonical
command. It is computed only from the acting seat's view, complete offered commands and existing
policy seed. This does not execute a game action. The browser skips worker inference for this
proposal and uses the existing leased, fenced, idempotent command submission. The server rechecks
the deterministic proposal at submission before the normal authoritative command driver. A mismatch
rejects without changing the game. No E/T private-state transport is added.

## Compatibility and admission

Latest local main is an ancestor of this feature. Its current UI files are retained exactly, together
with the preview's G3 reference hooks, C/P projections and old-rules asset routing. Stored histories,
leases, pending sealed submissions and older policy identities retain their existing contracts.
Any eventual preview uses a separate immutable runtime, port and fresh private storage; existing
services and games remain untouched.

Source verification uses constructed fixtures only: common/native selector parity including Support1,
cached asset identity and malformed-input rejection, server proposal scope/privacy/command equality,
legacy saves and bot lifecycle, and browser worker bypass with pause/reload/stale/uncertain writes.
Actual model packaging, fresh qualification streams/games and activation need their separate review.
