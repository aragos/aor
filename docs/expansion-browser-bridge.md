# Conditional expansion actor browser bridge

This source prerequisite makes an independently qualified schema-2 expansion actor usable through
the existing browser worker. It does not install an actor, replace current assets, restart a preview,
read human games, qualify a candidate or change ordinary bot behavior. Family-75 and family-78
experimental actors are not approved browser policies.

The isolated base is G3+support1 `df530fd6`, rebased onto local main `0040ce9`. The preserved clean
QoL checkpoint is `54e96b2`: only remaining-card ordering and personal competition presentation,
with their browser checks, differ from that preview. This bridge has its own branch and worktree.

## Public input and reference

`ExpansionObservationEncoder` remains the authoritative encoder. Extract an unbound
`ExpansionProjection` containing its existing encoder version, own/public state features and complete
canonically sorted offered actions. Its `bindBaseline` supplies the original offered command index;
no recommendation, model, seed, game identity, authority state or private opponent information enters
the projected payload. Existing `from` calls delegate to projection and binding without changing any
version-1 or version-2 values. Existing saves and all serialized engine state remain unchanged.

Only creator-authorized bot work gains an optional expansion projection from the actual acting
player's ordinary view. Projection is restricted to eligible Hard ordinary expansion windows under
the exact supported rules/catalog/setup. It is not included in public game snapshots. Existing lease,
decision, revision, submission-version and operation-receipt fences remain authoritative. Missing
fields from older clients/servers preserve the current controller; reads never execute a policy.

## Optional selector

Retain the existing card/purchase selectors and their callable contracts. A separately cached,
optional outer expansion selector is inactive without an explicit future qualified asset. The
ordinary composed selector first supplies its actual E recommendation for the same observation and
seed. The expansion projection must contain exactly those offered commands; binding preserves their
indices. The original `.97` prior, `TerritoryPolicy.actorSeed(EXPANSION, seed)`, Float64 residual
network and single uniform draw then choose one offered command. No later E overlay may replace it.

The narrowly admitted common model combination is schema 2 with
`aor-expansion-observation-2`; old schema-1 and encoder validity remain intact. An expansion asset
must bind its precise rules/catalog/setup, dictionary, ordinary/E reference and complete behavior
identity. Raw G3 and G3+support1 are different behavior compositions: qualification of one cannot be
silently claimed for the other. The concrete asset/export admission is separate from this inactive
source prerequisite and requires an actually qualified candidate.

Absent, malformed, mismatched or unsupported expansion input/assets return the original composed
choice. Card/purchase sampling, known-own-Chaos support, token ordering, ordinary E, other phases,
difficulties and legacy-rules fallback are unchanged. No manual action preference, additional search,
new reward, sampling temperature, mutable continuation queue or resampling is introduced.

## Verification and release boundary

Use constructed typed fixtures only. Verify projection/baseline equivalence and own/public privacy;
complete offers including singleton, card-buy, partial placement, attack, reduction and Cathedral
usage; schema/scope/dictionary rejection; and original-choice parity for absent or failed E inference.
Compare the exact native E reference and common actor with production Kotlin/JS serialization,
probabilities, selected command and log probability under fixed seeds and rounding boundaries.

Server checks retain old saves/controllers and missing payload fields, reject stale work and keep
expansion facts off public snapshots. Worker checks retain one cached selector, cancellation, stale
response suppression and no extra credentials or authority fields. Production StrictMode browser
checks must use live synthetic expansion offers, including legal submission and neighboring C/P/T
and known-own-Chaos behavior. Existing QoL browser checks also apply to the refreshed base.

During the two family-78 operational prefixes this task is read/edit only. After the explicit CPU
release, serialize low-parallelism formatting/checks and focused JVM/JS/server tests, production JS
and web builds, then the relevant browser suite. Source commits before that point are unverified
checkpoints. No asset activation or running-server change is part of this work.
