# Token paired-policy native prerequisite

This source-only prerequisite implements the native and portable inference boundary for the fixed
two-iteration token policy-improvement proposal. It does not initialize a scientific actor, reserve
streams, collect games, fit a model, change a preview or activate a policy. Campaign and numerical
owners separately freeze their protocols before any scientific execution.

## Policy and reference

The new explicit token contract uses model schema3 with `aor-token-observation-2`, the existing
64-wide Float64 territory residual network, .97 actual-reference prior, and existing token seed salt.
Its declared actor version is `aor-token-policy-2`. Schema1 TOKEN_1 and schema2 EXPANSION_2 retain
their existing meanings; old trajectory/bundle readers must reject the new actor rather than infer
compatibility from dimensions.

The controlled seat first uses the exact current frozen G3 card/purchase, M8/F0, expansion and fixed
token-order reference composition. A token wrapper obtains that complete controller's actual
recommendation once, binds it as the TOKEN_2 baseline, and makes one territory-policy draw. No outer
T controller may overwrite that result. Other decisions, including revealed tie-slot placement,
and every rival remain unchanged. The original pi0 actor and current iteration actor are separate
immutable subjects, even when their bytes coincide in iteration1.

The supported action set is the complete current public `tokenPurchaseOffers` set in canonical
command order. This is at most75 offers with the36-token stock; it is not all affordable integers.
The authoritative quote owner permits intermediate over-stock bids omitted by the suggestions.
Neither this experiment nor its exported evaluator expands that support.

## Origins, sharding and independent streams

Each iteration has640 prospective global origin indices. Indices0..511 are TRAIN and512..639 are
VALIDATION. The requested seat is `i % 4`, epoch `1 + (i / 4) % 3`, and own token-window ordinal
`1 + (i / 12) % 4` within that epoch. All counts include ordinary singleton windows. Missing and
singleton requested roots are retained without replacement or later-window substitution.

A shard declares one of ten64-aligned global ranges. Desktop owns chunks0..4 and8; Mac owns5..7
and9. Fixed global reproductions0,213,426,639 execute only in their owning shards. Each source binds the
same complete immutable stream table and scientific subjects as the other shards; host, worker
count and shard order cannot change the requested world, seat, root or streams. TRAIN/VALIDATION
assignment always uses the global index. The source explicitly supplies each origin's game seed,
one proposal RNG stream and two future chance streams. No hidden RNG expansion or refill is allowed.

Both prefixes and all continuations use the same frozen current iteration actor pi_m. Rival actors
and all non-token phases are fixed. At a captured branching root, retain the complete public
TOKEN_2 observation and exact reference action b. Sample min(8,n-1) distinct nonreference indices
uniformly, using only the declared proposal stream. Every nonreference action has inclusion
probability min(8,n-1)/(n-1); b is always included with probability1. All selected indices and public
probabilities are fixed before terminal tails are inspected. The numeric owner uses the exact
inclusion correction and reference delta0, not hindsight winner labels or sample-normalized policy.

All siblings share the two explicit future streams. Opponent sealed commitments are obtained from
the common pre-commit position, never from a position exposing another actor's current bid. The
original absolute PLAYER count and the shared sealed `batchStartNumber` remain distinct. Branches
replace only the controlled first action, then continue with fresh controllers of the same frozen
composition. Authority may produce ordinary random outcomes and terminal labels, but hidden state
never enters observations, proposal selection or model inputs.

## Evidence and anchor ownership

Every origin retains its source/request/stream subjects, public root observation, selected original
action indices, full pi_m/pi0 root probabilities, the canonical prefix, complete ordinary backbone
receipt and each paired tail's terminal/canonical receipt. Actor input and semantic terminal labels
are distinct trees. Separate immutable public and label sidecars bind the complete origin's raw
gzip hash, so VALIDATION public readers never need to decode its outcome tree. Source-level
snapshots preserve exact model and ecology identities independently of original path provenance.
Scientific labels are normalized controlled-seat terminal returns, never winner-selected actions.

Iteration1 TRAIN ordinary backbones additionally retain all own/public TOKEN observations and full
pi0 probabilities, with their original action/baseline identities. These are the fixed original
policy anchor population. Iteration2 TRAIN root observations add current-state anchor coverage;
the comparator stays the same pi0, not pi1. VALIDATION observations do not enter the fit or anchor.
All anchor weights and objective normalization belong to the separately reviewed numeric owner.

Worlds complete incrementally; workers return bounded completion receipts, not retained game trees.
Each origin has separate `public-I.json` and `labels-I.json` sidecars bound to its original compressed
evidence. The public sidecar contains no canonical or outcome tree; the label sidecar contains no
actor inputs. Missing and singleton windows retain their complete original normal backbones.
Host-independent ecology binds actual model/prior/dictionary/selector roles. Raw arena and joint
bundle wrapper hashes remain separate provenance because their component paths may be relocated.
Public metadata, canonical records and outcomes are hashed at completion. Every canonical suffix
must replay against its exact prefix, source and chosen command. The campaign owns verified archive
membership and original wall-clock/resource ceilings; the collector cannot resume or top up.

## Checks before scientific preparation

Constructed fixtures cover schema coupling and old-reader rejection, complete signed offer order,
exact current-T reference composition, no later overwrite, all sealed seats' seed/count mapping,
hidden-opponent-bid privacy, proposal uniqueness/inclusion probabilities and deterministic global
index sharding. Collector tests cover missing roots, independent sibling controllers, canonical
prefix/tail binding and TRAIN-only anchor retention without scientific games.

A production Kotlin/JS evaluator uses the same common actor and strict schema/observation decoder.
Constructed JVM output fixtures must match its full probabilities, values, selected command and
log probability at explicit uniforms, including zero/nonzero residuals, singleton and full offers.
Seed transformation receives its own common parity checks. No browser worker or model asset is
activated by exposing this evaluator.

Only the final second-iteration actor is eligible for the separately frozen development screen.
There is no validation-driven choice of epoch, iteration, settings or runner-up. This source
prerequisite changes neither the closed studies nor any production default policy.
