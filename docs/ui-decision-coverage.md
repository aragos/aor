# Visual decision coverage

Inventory follows `Stage.prompt`, `TurnEngine.phaseChoice`, the decision frames in `TurnFlow`,
`BoardGame`, `CardGame`, `PurchaseDecisions`, and `VariantInteractions`, and [canonical commands](commands.md).
A control being present is distinct from a browser interaction passing. “Pending” identifies a
verification gap. Fixture smoke checks exercise the complete App and canonical submission path with
deterministic transport; they do not establish domain validity or secrecy. Live checks use an isolated
real server. Authority outcomes are generated by the server.

Verification on 2026-10-27 passed 805 core and 124 server tests, Kotlin/JS compilation, Kotlin
formatting, eleven web unit checks, the production build, map validation and the focused browser suite.
The suite covers live commands and deterministic snapshots; its process groups and temporary game
and browser data were cleaned up. Screenshot review covered the fitted map, dense twelve-group
occupancy at Fit and practical zoom, the phone decision sheet and readable event cards.

The longer live three-player run on 2026-10-25 reached `FINISHED` through 473 checked canonical UI
actions across three epochs, with all players in Chaos and three final score rows. It was not rerun
for the latest refinements. Final Card Play has separate fixture coverage; that run did not visit it.

Run `npm run test:browser` from `web`. The runner owns an isolated server, Vite, Chrome profile and
game data, cleans them up on completion or failure, and prints the retained screenshot directory.
`CHROME_BIN` selects Chrome; `AOR_BROWSER_ARTIFACTS` selects the artifact directory;
`AOR_BROWSER_SERVER` uses an existing server launcher while still starting an isolated instance.

The default focused suite has a three-minute budget. To run the longer live scenario:

```sh
AOR_BROWSER_SUITE=fullgame.browser.mjs AOR_BROWSER_TIMEOUT_MS=1800000 npm run test:browser
```

It uses private seat tabs and visual controls, verifies actions through read-only snapshots, and
writes an action trace and result screenshot. Report the stages actually visited; a valid Chaos
ending does not establish deck-exhaustion or Final Card Play coverage.
