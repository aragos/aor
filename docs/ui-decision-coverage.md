# Visual decision coverage

Inventory follows `Stage.prompt`, `TurnEngine.phaseChoice`, the decision frames in `TurnFlow`,
`BoardGame`, `CardGame`, `PurchaseDecisions`, and `VariantInteractions`, and [canonical commands](commands.md).
A control being present is distinct from a browser interaction passing. “Pending” identifies a
verification gap. Fixture smoke checks exercise the complete App and canonical submission path with
deterministic transport; they do not establish domain validity or secrecy. Live checks use an isolated
real server. Authority outcomes are generated by the server.

Verification recorded on 2026-10-25: 732 core and 115 server tests, Kotlin/JS compilation,
Kotlin formatting, three web unit checks, the production build, and the focused browser suite passed.
A live three-player game reached `FINISHED` through 473 checked canonical UI actions across all
three epochs, ending with all players in Chaos and three final score rows. Final Card Play is covered
separately by a browser fixture; this live game did not reach that phase. A background-tab screenshot
timeout after completion was reproduced and fixed by focusing the capture tab; the targeted capture
check passed. Test servers, Vite, and Chrome process groups were verified closed after these runs.

Run `node scripts/browser-check.mjs` from `web` for isolated live browser checks. It builds the server
installation, chooses independent ports, and starts its own server, Vite and Chrome process groups.
It identifies child/helper processes by the exact process groups it created, terminates those owned
processes, verifies no live members remain, and removes temporary game/profile data in `finally`, on
success, failure, timeout, SIGINT or SIGTERM. Screenshots go to a separate temporary artifact directory
printed by the runner; set `AOR_BROWSER_ARTIFACTS` to retain them at a chosen location. Set `CHROME_BIN`
for a different Chrome executable. `AOR_BROWSER_SERVER` may point to an already built server launcher;
it skips the build but still starts and owns a fresh isolated server.

Select a separate suite with `AOR_BROWSER_SUITE=fullgame.browser.mjs`; override its time budget with
`AOR_BROWSER_TIMEOUT_MS` when running longer scenarios. The default focused suite has a three-minute
budget. Startup failure and an assertion failure have both exercised the cleanup path; no unrelated
browser processes are discovered or terminated.

Run the longer scenario from `web` with
`AOR_BROWSER_SUITE=fullgame.browser.mjs AOR_BROWSER_TIMEOUT_MS=1800000 npm run test:browser`.
It creates a game through the UI, keeps separate private player tabs, submits through visual controls,
and uses read-only snapshots to verify exact actions and final scores. It writes the action trace and
results screenshot to the artifact directory. A valid Chaos ending is accepted alongside deck
exhaustion; the trace records which stages were actually visited.
